# firmware-softuart

CAN 트랜시버를 물리 계층으로만 쓰고 실제로는 UART 신호를 싣는 현장에서, Robotell USB-CAN 어댑터로 그 UART 바이트를 받기 위한 펌웨어입니다.

> **검증 상태**: 빌드는 확인했지만(에러 0, 경고 0) 실제 보드에서의 동작은 아직 확인하지 않았습니다. 현장에 가져가기 전에 아래 "2대 연결 테스트"로 먼저 확인하세요.

## 배경

- UART의 idle(High)은 CAN의 recessive, UART의 Low는 CAN의 dominant에 대응합니다. 그래서 트랜시버 RXD 핀에는 UART 파형이 그대로 나옵니다.
- CAN 컨트롤러는 CAN 프레임만 해석하므로 이 신호를 받을 수 없고, 오히려 에러 프레임을 내보내 버스를 방해합니다.
- 트랜시버 RXD가 연결된 PB8은 하드웨어 USART 수신 핀이 아닙니다. 그래서 타이머로 UART를 직접 디코딩합니다(소프트웨어 UART).

## 동작 방식

| 방향 | 핀 | 방법 |
|---|---|---|
| 수신 | PB8 (TIM4_CH3) | 입력 캡처로 스타트 비트의 하강 엣지 시각을 하드웨어가 기록하고, 그 시각 기준으로 각 비트의 중앙을 샘플링합니다. |
| 송신 | PB9 (TIM4_CH4) | 출력 비교로 비트 경계마다 핀 레벨을 바꿉니다. 엣지 타이밍을 하드웨어가 만듭니다. |
| PC 연결 | USART2 | 받은 바이트를 포장 없이 그대로 PC로 보냅니다. |

CAN 컨트롤러는 아예 켜지 않습니다.

## 설정

`Source\SoftUart.h`에서 바꾸고 다시 빌드합니다.

| 항목 | 기본값 | 설명 |
|---|---|---|
| `SOFT_UART_Enable` | 1 | 0이면 `firmware-can`과 같은 USB-CAN 동작으로 빌드됩니다. |
| `SOFT_UART_TX_Enable` | 0 | 1이면 PC가 보낸 바이트를 버스로 송신합니다. **현장 버스에서는 반드시 0**으로 두세요. |
| `SOFT_UART_BAUDRATE` | 9600 | 현장 버스의 속도입니다. |
| `SOFT_UART_PARITY` | `SOFT_UART_PARITY_NONE` | `_EVEN`, `_ODD`로 바꿀 수 있습니다. |

수신 전용(`SOFT_UART_TX_Enable` = 0)일 때는 PB9를 High로 고정해 트랜시버를 recessive로 유지하므로 버스에 아무것도 내보내지 않습니다.

## 사용 방법

1. 어댑터의 CANH/CANL을 버스에 연결하고 USB를 PC에 꽂습니다.
2. PC에서 COM 포트를 **115200bps, 8N1**로 엽니다.
3. 버스에 실린 바이트가 그대로 올라옵니다.

- 데이터가 바이너리일 가능성이 높으므로 hex로 표시하는 터미널이나 직접 만든 프로그램으로 읽는 것이 좋습니다.
- 기존 Robotell 프로그램(패킷 형식 `AA AA … 55 55`)과는 호환되지 않습니다.
- PC 쪽 속도는 플래시에 저장된 값을 씁니다. `firmware-can`으로 값을 바꿔 저장한 적이 있으면 그 속도로 열어야 합니다.

## 2대 연결 테스트

현장에 가기 전에 어댑터 2대로 송수신을 확인할 수 있습니다.

1. `SOFT_UART_TX_Enable`을 1로 바꿔 빌드하고 두 대에 모두 굽습니다.
2. CANH끼리, CANL끼리 연결하고 CANH–CANL 사이에 120Ω 저항을 답니다.
3. 양쪽 PC에서 COM 포트를 115200bps 8N1로 엽니다.
4. 한쪽에서 보낸 바이트가 반대쪽에 그대로 올라오면 정상입니다.

테스트할 때 알아둘 점은 다음과 같습니다.

- 보낸 쪽 PC에도 같은 바이트가 되돌아옵니다. 트랜시버가 버스 상태를 그대로 RXD로 돌려주기 때문이며 정상입니다.
- 한 번에 255바이트까지만 보내세요. PC는 115200bps로 넣고 버스는 9600bps로 나가므로, 그보다 길게 연속으로 보내면 넘치는 바이트는 버려집니다.
- 양쪽이 동시에 보내면 데이터가 깨집니다. 선 한 쌍을 같이 쓰는 반이중 방식입니다.
- 2대 테스트는 송신과 수신을 같은 코드로 확인하는 것입니다. 가능하면 스코프로 비트 폭(9600bps면 104µs)을 재거나, 다른 9600bps 장비와도 한 번 맞춰 보세요.

테스트가 끝나면 `SOFT_UART_TX_Enable`을 0으로 되돌려 빌드한 펌웨어를 현장에 가져갑니다.

## 문제가 생겼을 때

| 증상 | 확인할 것 |
|---|---|
| 아무것도 안 올라옴 | 패리티 설정(현장이 8E1일 수 있음), 보레이트, CANH/CANL 극성 |
| 깨진 값이 올라옴 | 보레이트와 패리티. 디버거에서 `SoftUart_FramingErrors`, `SoftUart_ParityErrors`가 올라가는지 봅니다. |
| 바이트가 빠짐 | `SoftUart_OverrunErrors`(수신 버퍼 넘침), `SoftUart_TxOverrunErrors`(송신 버퍼 넘침) |

## 제약

- **속도**: 9600bps 기준으로 만들었습니다. 이 펌웨어는 인터럽트끼리 선점하지 않게 설정되어 있어(`NVIC_PriorityGroup_0`) 다른 인터럽트가 길어지면 샘플링이 밀립니다. 38400bps를 넘기려면 우선순위 구성을 바꿔야 합니다.
- **프레임 경계**: 바이트 사이의 공백 시간은 PC로 전달되지 않습니다.
- **설정 명령**: 이 모드에서는 PC에서 보내는 Robotell 설정 명령이 처리되지 않습니다.

## `firmware-can` 대비 바뀐 파일

| 파일 | 내용 |
|---|---|
| `Source\SoftUart.c`, `Source\SoftUart.h` | 소프트웨어 UART (새 파일) |
| `Source\Tasks.c` | CAN 태스크 대신 전달 태스크(`SoftUartForwardTask`)를 실행 |
| `Source\USART.c` | 송신 빌드에서 PC가 보낸 바이트를 `SoftUart_Write`로 전달 |
| `Project\USB2CAN.uvproj` | `SoftUart.c` 추가, 출력 이름을 `USB2CAN_SoftUart`로 변경 |
